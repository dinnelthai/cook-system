## 实测步骤

1. 使用已有的本地环境和独立确认的 genesis pin，检查 RPC HTTP/WS、Pump Lab 已有只读接口、现有 mint/pool 和数据覆盖区间。不使用公共网络代替。没有证据的项目标 UNKNOWN。
2. 如已有确认的封闭历史区间和独立保存的回执，按 local-read-acceptance-v1.md 的输入约定执行 accept:local-read（或通过 COOK_ACCEPT_EVIDENCE 等参数运行 accept:all）。样本 expected 值来自独立已有证据，不能先从被验收响应复制再声称验证通过。保留脱敏输出，区分抽样匹配与完整对账。
3. 在执行开关关闭的状态下，按 CODEX-ACCEPTANCE-PLAYBOOK.md 启动离线终端，真实浏览器检查六个导航页、导入失败提示、导出后重新导入、历史报告切换、控制台错误、合成/历史标签、K 线无数据状态和风险明细。允许查看已有钱包的公开余额/地址；不创建、充值、签名、转账、发行或买卖。检查现有操作入口实际是否存在，未实现记 NOT_IMPLEMENTED，交易等改变状态的功能记 NOT_TESTED，不为验收而开启或补写执行能力。
4. 用独立历史凭证检查 F01–F08 的实际数值。既有合成测试只说明确定性合同通过。缺少完整记录、独立估值、实际网络证据或截图时列出缺口。不要以覆盖标签 REPLAYED_FULL_HISTORY 代替算法正确性的结论。
5. 记录每个 F 项状态 PASS / FAIL / PARTIAL / UNKNOWN / NOT_IMPLEMENTED / NOT_TESTED。PASS 只能用于该项明确范围内已实测的事实。记录输入来源、期望值、实测值、差额、复现命令及证据路径；不得虚构样本、估值或回执。
6. 按 P0（阻断已有本地只读功能或造成错误账务）、P1（关键功能错误）、P2（一般体验问题）、P3（后续优化）整理 confirmed defects，另列未验证假设、未实现功能和缺失证据。禁止将交易策略优化、操纵市场或隐藏关联地址作为修复任务。
