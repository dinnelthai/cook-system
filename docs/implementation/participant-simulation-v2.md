# Participant simulation V2A — defensive robustness

The baseline synthetic fixture retains the existing illustrative role rules; issuer and ordering actors remain passive. V2A changes only generic QA scheduling and randomness: bounded seeded shuffled rounds, separately domain-keyed SHA-256 counter streams for each participant, scheduler and public information, and exact safe-integer seeds. Event timestamps remain ordered; execution latency is still a timestamp offset bounded to one tick, not a network execution model. No empirical independence or role realism is claimed.

A separate observation layer injects delayed/reordered, duplicate, missing, conflicting and corrupted event records into completed synthetic fixtures. Canonical event history is not mutated. It tests existing replay normalization and per-account ledger review, using the known canonical sequence for test-only coverage/content comparisons. In a real feed, equivalent independent evidence is needed; this oracle is not a production missing-record detector.

Run `npm run simulate:observation-stress -- /tmp/participant-observation-suite.json` (new output path required). Default 5 seed paths x 6 profiles = 30 synthetic QA cases. Tests cover domain separation, exact seeds, reproducibility, event order, ledger reconciliation, fault recovery, and fail-closed contradictions. Historical calibration, latency/holding-horizon/risk-preference dynamics, independent behavioral validation, genuine arbitrage/MEV modeling and real market accuracy remain unverified. No trading optimization, attack policies, signing or live RPC are introduced.

## V2B — SIM-02/03A: heterogeneous retrospective observers

Each completed synthetic path now supports independently reproducible observer profiles with different invented delay and missing-record parameters. Checkpoints separate canonically due, received, not-yet-due and missing-after-due records; these counts must reconcile exactly. Event age is unknown until a record is received. Profiles must match the synthetic agent set, are bounded, and cannot contain extra policy fields. The canonical report is independently re-reviewed before use; observations never modify its history or feed into trading behavior. The complete sequence is a test-only oracle, not a live missing-event detector. This is data-plane heterogeneity, not calibrated risk preference, holding horizon or market behavior. Run `npm run simulate:participant-coverage -- /tmp/participant-coverage.json` with a new path. Tests cover deterministic profiles, no future information, delayed recovery, total loss and invalid inputs.

## V2C — SIM-04A: market environment stress matrix

Adds fixed synthetic accounting tests for baseline, missing reserve evidence, valuation impairment and combined accounting/coverage stress; plus empty execution evidence and per-seed stale feed, delayed recovery, total outage and conflicting replay cases. Defaults to 25 cases across 5 seed paths. Accounting fixtures and generated event paths are intentionally distinct, not one reconciled simulated market. Low executable liquidity and actual low market activity are not established by missing data. The suite tests existing terminal, risk, replay and observer contracts; no actor policy change, calibrated market regimes, trading optimization, live RPC or execution. Run `npm run simulate:environment-stress -- /tmp/participant-environment-suite.json` with a new output path. Actual environment and empirical calibration remain open.

## V2D — SIM-05A: retrospective participant asset state review

Replays a completed synthetic fixture through the existing audited paired ledger postings. At bounded event-count checkpoints, records exact integer balances, balance shape (empty, quote only, token only, both assets), observed activity and state-change counts. Checks aggregate conservation after each recorded trade and compares final balances against the supplied endpoints even when only an early checkpoint was requested. Checkpoint digests can be compared to a fresh recomputation, not treated as authentication or a resumable runtime. Contradictory records suppress checkpoint output. Balance shape and activity never establish participant intent, exit, real ownership or future behavior. This is a retrospective asset-state model, not an adaptive agent policy. Run `npm run simulate:participant-state -- /tmp/participant-state-review.json` with a new path. Tests cover prefix consistency, endpoint reconciliation, corrupted checkpoints and bad event order. Historical calibration and real environment validation remain open.

## V2E — SIM-06/10A: unified validation and experiment review

One CLI runs seed-path ledger/state/observer checks, compound corruption detection, observation fault tests, environment contracts and fixed detector templates. Groups are reported separately; counts are not independent market outcomes or a real-world accuracy estimate. Default five seeds, 240 steps, 5 path cases + 30 observation cases + 25 environment cases + 20 fixed-template cases. Timing is measured only by CLI, outside the deterministic report digest. The unified acceptance runner now invokes this suite. Historical calibration readiness accepts optional archived closed-interval reports, recomputes existing checks and rejects exact duplicate intervals. No real data was provided, overlap and independent authentication are unverified, and no empirical fitting is performed. The market-risk page imports bounded result summaries and checks declared counts, not the digest or the actual run. Run `npm run simulate:validate -- /tmp/participant-validation.json` (optional second argument: local archived report array JSON). Remaining: actual independent historical calibration, dynamic behavior state policies, actual browser verification, real market validity and production performance. All suites are synthetic and non-executable.

## V2F — internal fixture boundaries before data integration

Data integration, empirical calibration and actual environment acceptance are deferred to the final phase. This iteration validates bounded scenario/agent identifiers, supported roles, duplicate IDs, canonical amount strings, aggregate amount bounds compatible with the ledger, and declared optional parameter types. It normalizes the accepted fields and rejects invalid reserve configurations. Existing illustrative synthetic arithmetic now suppresses degenerate records without changing balances if an effective amount, resulting reserve or represented price would be invalid. Tests cover empty accounts, tiny reserves, extreme fees, oversized and malformed input, and unchanged behavior for unused parameters. The generator version is bumped to participant-simulator.3. This is fixture correctness and resource-boundary hardening, not a new adaptive policy, an executable quote engine or a real-world behavior model. No real data or external connection is required.

## V2G — discrete observation clock

A bounded priority queue now processes offline observation arrivals at irregular integer millisecond timestamps, with stable insertion-order ties, duplicate-index rejection, no clock rewind, and no scheduling into an already processed time. The per-observer coverage model supports separate seeded delivery jitter, preserves canonical history, and computes freshness from the newest received event rather than the last arrival. Tests compare heap order with a stable sort, exercise limits, and verify delayed catch-up and coverage conservation. This is an observation-data clock only: the illustrative participant generator still uses fixed ticks, and no transaction ordering policy or live execution is added. Data integration remains deferred.

## V2H — SIM-C1: retrospective numeric evidence audit

A separate pure audit checks existing synthetic records for duplicate transaction references, exact represented price arithmetic, the declared embedded fee convention, positive intermediate reserves and closing reserve parity. The unified synthetic review and validation suite now include this check. Price and fee corruption tests demonstrate that balanced cash/token postings alone are insufficient. The audit does not calculate prospective quotes or validate real protocol fee attribution or the full market invariant. Unknown generator versions do not receive a numeric PASS. Data integration and empirical validation remain deferred.

## V2I — SIM-D1: participant asset coverage

Four fixed passive-account fixtures check empty accounts, mixed balance shapes, integer balances above JavaScript safe-number range and the maximum supported population (256 participants plus pool). Each checks exact balances, account counts, shape counts, no inferred activity, ledger/checkpoint recomputation and UNKNOWN numeric trade evidence for empty histories. The unified suite runs these checks within each seed-path case; the four top-level group counts remain unchanged. This is heterogeneous accounting coverage, not heterogeneous trading behavior, fitted participant wealth, ownership inference or a market optimization tool. No actual data is required.
