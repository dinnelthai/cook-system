# V0.8 archived account reconciliation

Read-only, offline Localnet evidence audit. Input scope: mode READ_ONLY, network localnet, genesisHash, wallet, tokenAccount, mint, openingSlot and closingSlot. Snapshots supply the same identifiers, slot, lamports and tokenAmount (unsigned integer strings preferred). Receipts supply genesisHash, finality FINALIZED, signature, transactionIndex and transaction (raw JSON RPC getTransaction result, including slot, message.accountKeys, signatures and full meta balance arrays). Opening slot is exclusive and closing slot inclusive; the snapshots are end-of-slot balances. Use complete historical receipts affecting the designated accounts, including failed transactions. Never substitute current balances for historical snapshots.

Run: node scripts/audit-archived-account.mjs interval.json

The audit checks scope, order, duplicate signatures and positions, native conservation including fees, token owner/mint continuity, failed transaction balance effects, and comparison with separately provided opening/closing observations. A missing token row is accepted as zero only for a demonstrably absent native account. Malformed evidence fails closed. The output is diagnostic only: source attestation stays UNKNOWN, history completeness is not attested, settlement and execution are disabled. Caller-supplied finality, genesis and coverage claims cannot be authenticated by offline arithmetic. Account creation, closure, unusual rent/reward effects and identity changes may need manual review. The audit covers one native account and one token account, not all custody accounts, wrapped SOL, market attribution, cost basis or PnL. The existing historical accounting engine is not automatically populated from this report. No network access, wallet signing or transaction submission is added.
