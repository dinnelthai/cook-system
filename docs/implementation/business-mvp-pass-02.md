# Business MVP pass 02 — project setup, issuance evidence and wallet portfolio
B02 adds a browser-local project registry for project preparation: name, symbol, description, integer supply, decimals (0–9), SOL quote asset, Localnet environment, optional managed Dev Wallet and HTTPS links. Atomic supply is checked against u64. Draft status is DRAFT or CONFIGURED_NOT_ISSUED. An operator may attach a mint and transaction signature as an issuance evidence record; the state remains UNVERIFIED / NOT_PERFORMED. There is deliberately no UI action that can mark a project as issued, and no mint transaction or signer path was added. Project data is browser localStorage; export is provided. This is a local draft registry, not a multi-user database.
B03 adds a read-only local wallet portfolio endpoint. It only enumerates addresses in the managed wallet store, pins the RPC to a loopback HTTP endpoint and exact non-public-cluster genesis hash, then reads SOL balances, classic SPL and Token-2022 accounts, and recent parsed transaction signatures. Balances remain raw units; no price or USD valuation is inferred. Failed reads remain null / UNAVAILABLE, not zero. The UI shows per-wallet SOL, aggregated mint balances and recent transaction status/parsed transfers. The service never loads a signer and does not add transfer, airdrop, trading or execution capabilities.
Manual acceptance remains required against the user's own Localnet: create two managed wallets, fund one, transfer SOL, refresh portfolio, verify balances and signatures, create a project draft bound to a managed wallet, export/reload browser storage, register a sample mint/signature and confirm it remains UNVERIFIED. Public clusters must be rejected. No actual token issuance is implemented.
