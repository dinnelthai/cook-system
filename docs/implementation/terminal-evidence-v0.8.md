# V0.8 integrated historical terminal evidence

Optional archivedEvidence = {schema_version:"cook-terminal-evidence.1", accountInterval}. The historical report itself must use ARCHIVED_HISTORICAL mode and SOL_LAMPORTS quote. Extend all report section scope objects with network:"localnet", genesisHash, wallet and tokenAccount, and set openingCutoff/closingCutoff to "slot:<slot>". Report tokenMint must match the account interval mint. Each existing cash posting must include its receipt signature. The adapter recomputes the receipt and cash crosscheck from raw evidence and uses those same report postings; it rejects imported audit summaries and mismatched scopes. It compares opening/closing cash and token amounts, and a discrepancy suppresses financial metrics in terminal state. Existing reports with no evidence remain importable, but the evidence is explicitly unavailable. The browser displays the result under risk/audit. File import is capped at 16 MiB, matching the local report bridge. This does not authenticate caller supplied genesis/finality/ownership/coverage, establish cost basis from receipts, or establish settlement. The existing historical dashboard outside terminal state continues its independent internal report calculation. The content-addressed event store is a separate Node archival module and is not yet linked to terminal evidence. No live execution, trading changes, or new permission is added.

See test/terminal-evidence.test.mjs for a complete synthetic receipt fixture of a historical-mode report (not real chain evidence).
